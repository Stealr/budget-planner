# Бэкенд

REST API операций и категорий на Java 21 и Spring Boot. PostgreSQL хранит данные, Liquibase управляет миграциями.

Для запуска всех сервисов используйте [Compose из корня репозитория](../README.md#запуск-в-docker).

Для разработки бэкенда отдельно можно поднять только PostgreSQL и запустить Spring Boot с локальным JDK 21. Выполните из каталога `backend`:

```powershell
docker compose up -d --wait postgres
.\gradlew.bat bootRun
```

В этом режиме PostgreSQL доступен на порту `5433`, API — на порту `8080`.

## Регистрация и вход

Передавайте JSON с полями `email` и `password` в `POST /api/v1/auth/register`.
Успешная регистрация возвращает `201` и поля `id` и `email`. Занятый email
возвращает `409`. Email приводится к нижнему регистру. Пароль должен содержать
минимум 8 символов и занимать не более 72 байт в UTF-8.

`POST /api/v1/auth/login` принимает те же поля и возвращает `200` с
`accessToken`, `tokenType` и `expiresAt`. Токен действителен 24 часа по умолчанию. Срок можно задать через `APP_AUTH_ACCESS_TOKEN_TTL` (например, `PT2H`). В БД хранится SHA-256 токена. Просроченные токены удаляются раз в час. Интервал задаётся через `APP_AUTH_CLEANUP_INTERVAL`.
При неверном email или пароле API возвращает `401` с общим сообщением.

Передавайте `Authorization: Bearer <accessToken>` в запросах к категориям
операциям и лимитам. В Swagger UI вставьте токен через **Authorize**. Списки содержат
стандартный каталог и категории текущего аккаунта. Операции и лимиты видны только владельцу. Запросы к чужим записям по ID возвращают `404`.

Миграция сохраняет существующие категории и операции без владельца.
Они не видны через API аккаунтов. Для переноса таких данных нужно явно
назначить владельца категориям, операциям и лимитам.

## Категории

Liquibase добавляет десять стандартных категорий. Поле `standard` отличает
каталог от созданных пользователем категорий. Стандартные категории защищены
от переименования, удаления и архивирования.

- `GET /api/v1/categories` возвращает активные категории.
- `GET /api/v1/categories?includeArchived=true` включает архив. Поле
  `archivedAt` содержит дату архивации или `null`.
- `PATCH /api/v1/categories/{id}/archive` архивирует пользовательскую
  категорию и возвращает `204`. Повторный вызов сохраняет дату архивирования.
- `DELETE /api/v1/categories/{id}` удаляет пользовательскую категорию без
  связанных операций и лимитов. При наличии связей API возвращает `409`.

Новые операции и перенос операций в архивную категорию отклоняются с `409`.
Исторические операции доступны для чтения и редактирования с прежней
категорией. Ответ операции содержит `categoryName` для отображения истории.

## Месячные лимиты

Месяц передаётся как `YYYY-MM`. Лимит задаётся в рублях для активной
категории расходов. На аккаунт, категорию и месяц приходится одна запись.

- `PUT /api/v1/limits/{categoryId}?month=2026-11` создаёт или обновляет
  лимит. Тело запроса — `{"amount": 5000.00}`.
- `GET /api/v1/limits?month=2026-11` возвращает все лимиты месяца.
- `GET /api/v1/limits/{categoryId}?month=2026-11` возвращает один лимит.
- `DELETE /api/v1/limits/{categoryId}?month=2026-11` удаляет лимит.

Ответ содержит `limitAmount` и `spentAmount`. Расходы считаются по датам
операций с первого дня месяца до первого дня следующего месяца. При
архивировании категории существующие лимиты остаются доступны для просмотра
и удаления.
