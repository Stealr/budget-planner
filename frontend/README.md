## Данные и состояние

- **RTK Query** ведёт кеш операций и категорий. После успешного добавления операции инвалидируем теги `Transactions`, `Dashboard` и `Limits` для последующей интеграции сводок.
- **Redux-слайсы** хранят состояние сессии и мобильного меню. Запросы регистрации и входа используют отдельный `fetch`: пароль не попадает в Redux, его действия и кеш RTK Query.
- **Формы** хранят поля, включая пароль, локально. В `sessionStorage` сохраняются только `accessToken`, `tokenType`, `expiresAt`.

## Авторизация

`/login` и `/register` доступны без входа; остальные маршруты защищены. Регистрация создаёт аккаунт, затем открывает вход с заполненным email. Пароль регистрации — от 8 символов до 72 байт UTF-8, без нулевого символа. Пробелы в пароле сохраняются.

После входа пользователь возвращается на исходную внутреннюю страницу вместе с параметрами и якорем. Сессия восстанавливается синхронно до запросов защищённых страниц. Токен непрозрачный, API получает его как `Authorization: Bearer …`.

Сессия действует в пределах вкладки и переживает обновление страницы. Если браузер запретил `sessionStorage`, она сохраняется только до перезагрузки. При истечении `expiresAt`, ответе `401` защищённого API или нажатии «Выйти» сессия и кеш очищаются, активные запросы отменяются. Запоздалый ответ предыдущего аккаунта не может заполнить кеш нового или завершить его сессию. `401` при неверном пароле остаётся ошибкой формы входа.

На сервере нет refresh и logout: после истечения требуется повторный вход, а выход очищает клиентскую сессию без отзыва токена на сервере.

## Проверки

- **Vitest** проверяет валидацию и восстановление сессии, безопасный адрес возврата.
- **React Testing Library и MSW** проверяют регистрацию, вход, ошибки, выход, истечение сессии, Bearer-заголовок и смену аккаунта с запоздавшими ответами.
- **axe-core** проверяет доступность форм. Проверка контраста и реальной адаптивной вёрстки выполняется в браузере.

Из корня: `npm test`; для наблюдения за тестами — `npm exec --workspace frontend -- vitest`.
CI выполняет `npm run lint`, `npm run format:check`, `npm run build`, `npm test`.

## Текущий каркас

Работают регистрация и вход, история и добавление расхода, список и создание категорий. Дашборд, лимиты, импорт и настройки пока открывают экраны каркаса.

Общий модуль RTK Query находится в `src/store/api.ts`. По умолчанию он использует `/api` на том же домене. Для отдельного адреса API задайте `VITE_API_BASE_URL` при запуске Vite. Эндпоинты подключены через `api.injectEndpoints` в `src/transactions/api.ts` и `src/categories/api.ts`. Авторизация находится в `src/auth/`.

## Запуск сценария добавления расхода

Для запуска всего приложения выполните из корня `docker compose up -d --build --wait` и откройте [«Операции»](http://localhost:8080/transactions). Сначала зарегистрируйтесь и войдите.

Для локальной разработки понадобятся Docker, JDK 21 и Node.js 24+. В отдельных терминалах запустите PostgreSQL, Spring Boot и Vite:

```powershell
# Из корня репозитория
docker compose -f backend/docker-compose.yml up -d --wait postgres
```

```powershell
Set-Location backend
.\gradlew.bat bootRun
```

```powershell
# Из корня репозитория
npm ci
npm run dev
```

Vite проксирует запросы `/api` на `http://127.0.0.1:8080`. При размещении фронтенда отдельно задайте `VITE_API_BASE_URL` с путём `/api` и настройте доступ к API.

Миграция создаёт десять стандартных категорий. Создавать категорию вручную для первого расхода не требуется. Прямые запросы к API вне фронтенда требуют заголовок `Authorization: Bearer <accessToken>` после `POST /api/v1/auth/login`; контракт описан в [README бэкенда](../backend/README.md).

1. Зарегистрируйтесь, войдите, откройте раздел «Операции» и нажмите «Добавить расход».
2. Введите `450,50`, выберите стандартную категорию расхода, оставьте сегодняшнюю дату и сохраните. Новые записи показываются первыми.
3. Перезагрузите страницу и проверьте, что запись осталась в списке.
4. Для проверки отказа создайте отдельную собственную категорию расхода без операций, выберите её в форме и удалите через `DELETE /api/v1/categories/{id}` с Bearer-токеном до сохранения. При сохранении API вернёт `404`, форма покажет ошибку категории и новая операция не появится.
5. Выйдите и войдите другим аккаунтом: собственные категории и операции первого аккаунта не должны показываться.
